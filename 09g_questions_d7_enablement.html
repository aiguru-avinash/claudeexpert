Q141D7Intermediate

Objective: Configure shared team tooling and standards

Scenario

A 40-engineer team uses Claude Code. Each developer re-explains build commands, conventions, and test rules every session.

Question

What is the best fix?

  1. AMaintain a project-level CLAUDE.md in version control with build/test commands, conventions, architecture notes, and "do not" rules, reviewed like code.
  2. BAsk each developer to paste a long prompt each session.
  3. CStore the guidance in a wiki no one links to.
  4. DRely on the model remembering previous sessions.
Show answer & explanation

Correct answer A

Explanation

Shared, versioned project memory gives every session consistent context.

Why not the others

B is manual and inconsistent; C isn't loaded into context; D is unreliable.

Architectural principle

Encode team knowledge where the tool reads it.

Reference

Claude Code docs: memory / CLAUDE.md

Q142D7Advanced

Objective: Configure shared team tooling and standards

Scenario

Security wants to prevent the coding agent from reading secrets files or running destructive shell commands, for every developer.

Question

What is the strongest approach?

  1. AAdd "don't read secrets" to CLAUDE.md only.
  2. BTrust developers to deny prompts.
  3. CCommit shared permission rules (deny for secret paths and dangerous commands, allow-list for routine ones), and use managed or organization-level settings where policy must not be overridden; add hooks for enforcement and audit.
  4. DDisable the tool for the team.
Show answer & explanation

Correct answer C

Explanation

Deterministic permission rules and managed policy enforce what instructions can only request.

Why not the others

A is advisory; B is inconsistent; D abandons the productivity goal.

Architectural principle

Enforce with configuration, not advice.

Q144D7Advanced

Objective: Establish developer workflows with AI assistance

Scenario

The team wants an agent to review pull requests in CI.

Question

Which design is most appropriate?

  1. ALet the agent merge PRs automatically.
  2. BGive the CI job broad production credentials.
  3. CSkip human review once the agent approves.
  4. DRun it with read-only repo access and minimal scoped credentials, post comments for humans to act on, treat PR content as untrusted input, and keep human approval required for merge.
Show answer & explanation

Correct answer D

Explanation

Least privilege plus untrusted-input handling and human approval limit risk.

Why not the others

A and C remove oversight; B violates least privilege.

Architectural principle

Least privilege and human gate in automation.
