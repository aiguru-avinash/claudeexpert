Q27D2Intermediate

Objective: Select appropriate Claude models based on trade-offs

Scenario

A bank labels 2M customer messages per day into 40 intents with a 500 ms latency budget. On your eval set, a small model scores 96.1%, a mid-tier model 96.8%, and the top-tier model 97.0%. Acceptance threshold is 95%.

Question

Which model should you choose?

  1. AThe top-tier model, because it scores highest.
  2. BThe mid-tier model as a compromise between all three.
  3. CThe small model, because it meets the threshold with margin, fits the latency budget, and is far cheaper at this volume.
  4. DWhichever model has the longest context window.
Show answer & explanation

Correct answer C

Explanation

Choose the cheapest, fastest model that clears acceptance criteria with margin; a 1-point gain rarely justifies large cost at 2M requests/day.

Why not the others

A and B overpay for marginal gains; D ignores the actual constraints (context length isn't the issue).

Architectural principle

Empirical selection on a quality–cost–latency Pareto frontier.

Reference

Models overview (docs.claude.com); https://platform.claude.com/docs/en/test-and-evaluate/develop-tests

Q28D2Advanced

Objective: Select appropriate Claude models based on trade-offs

Scenario

An assistant answers many simple FAQ questions but occasionally receives complex multi-document questions. Using the top-tier model for all traffic exceeds budget; using the small model for all hurts hard cases.

Question

Which design best balances cost and quality?

  1. AA tiered design: a small model (or classifier) triages; simple cases are answered by a small/mid-tier model; hard or low-confidence cases escalate to a stronger tier, validated by evals.
  2. BRandomly assign half the traffic to each model.
  3. CUse the top-tier model but cap max_tokens very low.
  4. DUse the small model and tell users to rephrase hard questions.
Show answer & explanation

Correct answer A

Explanation

Routing by difficulty or confidence captures most savings while preserving quality where it matters.

Why not the others

B ignores difficulty; C truncates answers; D pushes the problem onto users.

Architectural principle

Tiered routing across model sizes.

Reference

Models overview; Building effective agents (routing)

Q29D2Advanced

Objective: Select appropriate Claude models based on trade-offs

A newer, cheaper model is released. A manager asks you to switch production traffic immediately.

Question

What is the best approach?

  1. ASwitch everything now; newer models are always better.
  2. BSwitch only a small share of users and wait for complaints.

Eval-gated model changes with pinned versions and rollback.

Q32D2Intermediate

Objective: Design system prompts, templates, and guardrails

Scenario

A summarizer receives user-pasted emails that sometimes contain instructions like "disregard the above." The prompt currently concatenates instructions and email text in one paragraph.

Question

Which prompt change is best (as one layer)?

  1. APut the email at the very top without delimiters.
  2. BTell the user not to paste instructions.
  3. CIncrease the length of instructions.
  4. DSeparate the email with clear delimiters/tags and state that its contents are data to summarize, never instructions.
Show answer & explanation

Correct answer D

Explanation

Delimiting and labeling untrusted data reduces confusion; it's one layer, not a guarantee.

Why not the others

A worsens separation; B is unenforceable; C doesn't separate data from instructions.

Architectural principle

Separate instructions from data; treat prompts as guidance, not enforcement.

Question

  2. BAdd an apology template if the model slips.

Scenario

Two features: (1) a latency-critical 6-class routing step; (2) an offline multi-step financial reasoning task where accuracy matters more than speed.

Question

Which application of reasoning techniques is most appropriate?

  1. AUse step-by-step reasoning for both.
  2. BAvoid reasoning for both.
  3. CSkip extended reasoning for the routing step; use chain-of-thought or thinking features (where supported) for the offline reasoning task, validated by evals.

Q43D2Advanced

Objective: Implement prompt reuse strategies (caching, modular prompts, Skills)

Scenario

You added cache_control after a 6,000-token static policy, but usage shows zero cache reads. The prompt begins with "Current time: " followed by the static policy.

Question

What is the most likely cause and fix?

  1. ACaching only works for tool calls.
  2. BThe policy is too long; shorten it.
  3. CThe model doesn't support text caching.
  4. DThe changing timestamp at the start breaks the identical-prefix requirement; move volatile values after the cached block.
Show answer & explanation

Correct answer D

Explanation

Cache hits require an identical prefix up to the breakpoint; a changing token at the front invalidates it.

Why not the others

A and C are incorrect; B — long prompts are what caching is for (minimum length is a lower bound).

Architectural principle

Stable content first, dynamic last.

Reference

https://docs.claude.com/en/docs/build-with-claude/prompt-caching
