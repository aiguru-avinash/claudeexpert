Original practice questions; not official or leaked. Objectives quoted from Exam Guide v1.0 §6 D3. Domain 3 is the heaviest at 19%.

Q46 · D3 · Objective: Evaluate tool/agent configuration for capability bloat · Difficulty: Intermediate

Scenario: An internal assistant exposes 45 tools to every conversation. Traces show frequent wrong-tool choices and 7,000 tokens of tool definitions per request. Question: Which change is best? A. Increase max_tokens. B. Scope tools to the task or role and add on-demand tool discovery for the rest; re-run tool-selection evals. C. Add a prompt line: "Choose tools carefully." D. Switch to a model with a larger context. Correct answer: B Explanation: Fewer, scoped tools reduce confusion and tokens; discovery loads detail only when needed. Why not the others: A and D don't reduce confusion or cost; C is not an enforcement of anything. Architectural principle: Least capability plus progressive discovery. Ref: Prep Lesson 2; Agent Skills (progressive disclosure)

Q47 · D3 · Objective: Evaluate tool/agent configuration for capability bloat · Difficulty: Intermediate

Scenario: A business-intelligence assistant only answers read-only questions, but its database tool runs under a role that can also INSERT and DELETE "in case we need it later." Question: What is the best correction? A. Log all write statements for later audit. B. Add a system-prompt rule: "Never write to the database." C. Ask the model to confirm before writing. D. Run the tool under a read-only role (and restrict tables/rows), creating a separate, gated path if writes are ever needed. Correct answer: D Explanation: Removing unneeded privilege eliminates the risk; monitoring and prompts only compensate. Why not the others: A is detective; B and C depend on model compliance. Architectural principle: Preventive controls (least privilege) beat detective or compensating ones. Ref: Prep Lessons 2–3

Q48 · D3 · Objective: Evaluate tool/agent configuration for capability bloat · Difficulty: Advanced

Scenario: The tool list includes search_docs, find_documents, and lookup_docs with nearly identical descriptions; the agent uses them inconsistently and results vary. Question: What should you do? A. Consolidate into one well-specified tool (or clearly differentiate the purposes) with precise, non-overlapping descriptions and schemas; then re-evaluate. B. Add more tools with other names. C. Randomize tool order each request. D. Add examples showing all three used at once. Correct answer: A Explanation: Overlap causes ambiguous selection; consolidation or crisp differentiation improves reliability. Why not the others: B worsens it; C adds noise; D increases confusion. Architectural principle: Tool design: distinct purposes, clear contracts. Ref: Tool use docs

Q49 · D3 · Objective: Evaluate tool/agent configuration for capability bloat · Difficulty: Intermediate

Q50 · D3 · Objective: Analyze authentication and authorization requirements to identify security gaps · Difficulty: Advanced

Scenario: A CRM agent uses a single administrator token for all lookups. A junior rep asks about a restricted VIP account and the agent returns it. Question: Which is the most important fix? A. Add "respect permissions" to the prompt. B. Hide the account name in the response. C. Propagate the end user's identity (on-behalf-of / user-scoped tokens) so the CRM enforces that user's entitlements. D. Reduce the number of CRM fields the model can see. Correct answer: C Explanation: The shared super-user token makes the agent a confused deputy; backend enforcement per user closes the gap. Why not the others: A relies on the model; B and D are cosmetic or partial. Architectural principle: Authorize with the user's identity at the system of record. Ref: MCP authorization spec; Prep Lesson 3

Q51 · D3 · Objective: Analyze authentication and authorization requirements to identify security gaps · Difficulty: Advanced

Scenario: A get_invoices tool takes tenant_id and customer_id as arguments supplied by the model. Question: What is the primary risk and fix? A. Latency; cache invoice results. B. The model (or an injected instruction) can request another tenant's data; derive tenant from the authenticated session and validate all arguments server-side. C. Token cost; shorten argument names. D. Formatting; require uppercase IDs. Correct answer: B Explanation: Model-supplied identifiers are untrusted input; authorization must use authenticated context. Why not the others: The other options don't address cross-tenant access. Architectural principle: Never trust model-supplied authority; validate server-side. Ref: Prep Lesson 3

Q52 · D3 · Objective: Analyze authentication and authorization requirements to identify security gaps · Difficulty: Expert

Scenario: An HTTP-based MCP server accepts any valid OAuth token from the company's identity provider, including tokens issued for other internal APIs, and forwards them downstream. Question: What is the gap and the best fix? A. No gap; any company token is fine. B. Switch the server to stdio so OAuth isn't needed. C. Hide the server URL. D. Tokens must be issued for, and validated against, the MCP server as the intended audience; the server must not pass through tokens meant for other resources, and each tool must still apply its own data authorization. Correct answer: D Explanation: Audience binding prevents token confusion; passing tokens through breaks trust boundaries; protocol-level auth doesn't replace per-tool authorization. Why not the others: A ignores confused-deputy risk; B changes transport and credential handling, not the gap; C is obscurity. Architectural principle: Audience-bound tokens, no passthrough, and per-resource authorization. Ref: https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization

Q53 · D3 · Objective: Analyze authentication and authorization requirements to identify security gaps · Difficulty: Advanced

Scenario: A shared vector index serves several tenants. The app retrieves top-k chunks, sends them to Claude, then removes sentences from the answer that "look confidential." Question: What is the most important correction? A. Apply tenant/ACL filters at retrieval time so unauthorized chunks never reach the model. B. Increase k to find more safe chunks. C. Add a disclaimer to the answer. D. Fine-tune the model to avoid confidential text. Correct answer: A Explanation: Post-hoc filtering is unreliable and the model has already seen the data. Why not the others: B, C, and D don't enforce access boundaries. Architectural principle: Entitlement filtering before context. Ref: Prep Lessons 2–3

Q54 · D3 · Objective: Analyze authentication and authorization requirements to identify security gaps · Difficulty: Advanced

Question (Select TWO): Which are authorization gaps? A. One shared API key embedded in the system prompt and used for every user's requests. B. User-scoped, short-lived tokens exchanged per request. C. Entitlement checks performed only after retrieved text has been sent to the model. D. A broker that validates tool arguments against a schema. E. Audit logs recording user and agent identity. Correct answers: A, C Explanation: Shared embedded credentials and after-the-fact filtering both defeat least privilege. Why not the others: B, D, and E are good controls. Architectural principle: Identify where authority is granted and where it's checked. Ref: Exam Guide D3/D5

Q55 · D3 · Objective: Evaluate accuracy-latency trade-offs and justify configuration decisions · Difficulty: Intermediate

Scenario: A consumer chat feature needs the first words to appear within a second; answers are moderate in length; quality on the eval set is acceptable with a mid-tier model. Question: Which configuration best supports the goal? A. Use batch processing. B. Add a verification pass to every answer. C. Stream responses, cache the static prefix, keep max_tokens appropriate, and use the lowest model tier that clears quality targets. D. Use the largest model and rely on streaming alone. Correct answer: C Explanation: Streaming improves perceived latency; caching and right-sizing reduce time-to-first-token and cost. Why not the others: A is asynchronous; B adds latency; D increases latency and cost. Architectural principle: Combine streaming, caching, and right-sizing for interactive latency. Ref: Streaming docs; prompt caching docs

Q56 · D3 · Objective: Evaluate accuracy-latency trade-offs and justify configuration decisions · Difficulty: Advanced

Scenario: A second "verification" model call doubles latency. Errors in low-risk draft replies cost little; errors in refund approvals are expensive. Question: What is the best configuration decision? A. Remove verification everywhere. B. Apply verification (and stronger models) selectively to high-risk actions, and skip or lighten it for low-risk drafts, justified with eval data. C. Apply verification everywhere regardless of risk. D. Use verification only when the user complains. Correct answer: B Explanation: Risk-tiered configuration spends latency/cost where errors are costly. Why not the others: A and C ignore risk differences; D is reactive. Architectural principle: Allocate accuracy effort by error cost. Ref: Prep Lesson 2

Q57 · D3 · Objective: Evaluate accuracy-latency trade-offs and justify configuration decisions · Difficulty: Advanced

Scenario: Month-end spikes cause 429 errors. Retries create duplicate refund tickets in the downstream system. Question: Which combination is best? A. Increase retries to 20 with no delay. B. Remove retries. C. Ask the model not to refund twice. D. Exponential backoff with jitter honoring retry-after, a queue with concurrency limits, and idempotency keys on write operations. Correct answer: D Explanation: Backoff and queuing manage load; idempotency prevents duplicate side effects on retry. Why not the others: A worsens the storm; B drops legitimate requests; C is not a control. Architectural principle: Resilience with idempotent writes. Ref: https://docs.claude.com/en/api/rate-limits

Q60 · D3 · Objective: Analyze observability challenges and select monitoring strategies at scale · Difficulty: Advanced

Q62 · D3 · Objective: Design a RAG pipeline with appropriate chunking and indexing strategies · Difficulty: Advanced

Q63 · D3 · Objective: Design a RAG pipeline with appropriate chunking and indexing strategies · Difficulty: Intermediate

Q67 · D3 · Objective: Evaluate progressive discovery vs. monolithic context strategy · Difficulty: Intermediate
