Q46D3Intermediate

Objective: Evaluate tool/agent configuration for capability bloat

Scenario

An internal assistant exposes 45 tools to every conversation. Traces show frequent wrong-tool choices and 7,000 tokens of tool definitions per request.

Question

Which change is best?

  1. AIncrease max_tokens.
  2. BScope tools to the task or role and add on-demand tool discovery for the rest; re-run tool-selection evals.
  3. CAdd a prompt line: "Choose tools carefully."
  4. DSwitch to a model with a larger context.
Show answer & explanation

Correct answer B

Explanation

Fewer, scoped tools reduce confusion and tokens; discovery loads detail only when needed.

Why not the others

A and D don't reduce confusion or cost; C is not an enforcement of anything.

Architectural principle

Least capability plus progressive discovery.

Q47D3Intermediate

Objective: Evaluate tool/agent configuration for capability bloat

Scenario

A business-intelligence assistant only answers read-only questions, but its database tool runs under a role that can also INSERT and DELETE "in case we need it later."

Question

What is the best correction?

  1. ALog all write statements for later audit.
  2. BAdd a system-prompt rule: "Never write to the database."
  3. CAsk the model to confirm before writing.
  4. DRun the tool under a read-only role (and restrict tables/rows), creating a separate, gated path if writes are ever needed.
Show answer & explanation

Correct answer D

Explanation

Removing unneeded privilege eliminates the risk; monitoring and prompts only compensate.

Why not the others

A is detective; B and C depend on model compliance.

Architectural principle

Preventive controls (least privilege) beat detective or compensating ones.

Q50D3Advanced

Objective: Analyze authentication and authorization requirements to identify security gaps

Scenario

A CRM agent uses a single administrator token for all lookups. A junior rep asks about a restricted VIP account and the agent returns it.

Question

Which is the most important fix?

  1. AAdd "respect permissions" to the prompt.
  2. BHide the account name in the response.
  3. CPropagate the end user's identity (on-behalf-of / user-scoped tokens) so the CRM enforces that user's entitlements.

Q52D3Expert

Objective: Analyze authentication and authorization requirements to identify security gaps

Scenario

An HTTP-based MCP server accepts any valid OAuth token from the company's identity provider, including tokens issued for other internal APIs, and forwards them downstream.

Question

What is the gap and the best fix?

  1. ANo gap; any company token is fine.
  2. BSwitch the server to stdio so OAuth isn't needed.
  3. CHide the server URL.
  4. DTokens must be issued for, and validated against, the MCP server as the intended audience; the server must not pass through tokens meant for other resources, and each tool must still apply its own data authorization.
Show answer & explanation

Correct answer D

Explanation

Audience binding prevents token confusion; passing tokens through breaks trust boundaries; protocol-level auth doesn't replace per-tool authorization.

Why not the others

A ignores confused-deputy risk; B changes transport and credential handling, not the gap; C is obscurity.

Architectural principle

Audience-bound tokens, no passthrough, and per-resource authorization.

Reference

https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization
